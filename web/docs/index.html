Devcenter documentation

Devcenter is the authenticated browser application and deliberately narrow backend-for-frontend for independent identity, agent, workflow, connector, workspace, and execution services.

Sign in

GET /auth/sso/start begins generic OpenID Connect login through the configured Identity service. Devcenter stores only an opaque, secure browser-session cookie. Provider branding and deployment-specific organization policy remain outside this repository.

Connect Claude Code

After signing in, paste a user-owned subscription credential into the Connect Claude form. Devcenter forwards it once to Connectors over the internal service network. Connectors owns encrypted custody, replacement, revocation, and future refresh behavior; neither the browser application nor Agent Platform persists the credential.

Attempt boundary. When the user starts a task, Agent Platform requests an exact attempt-bound lease. Harness redeems that lease only when making the provider call.

Create and run an agent

The dashboard creates an agent, writes its first revision, activates it, and then accepts prompts as Tasks. Results arrive as ordered server-sent events from /api/tasks/{task_id}/events. The first slice runs in-process; durable workers and recovery are separate deployment milestones.

API and MCP

The deterministic OpenAPI document describes the BFF allowlist. /mcp exposes the governed composition surface to authenticated clients; it does not provide an unrestricted proxy to inner services.

Deployment

The public Helm chart is configuration-neutral. Supply tenant policy, hosts, immutable private image references, storage, secret references, and any private connector catalog bundle from a separate deployment repository. The chart supports internal ingress and GitLab Agent for Kubernetes deployments without embedding either provider’s identity into the product.
